# Performance update — 2026-09-28

This update implements the first four priorities from the project performance review.

## Changes

- Capture listing, storage statistics, JPEG/JSON reads, capture publication, and
  startup/hourly retention scans run in worker threads. Camera HTTP requests
  remain asynchronous. A per-store reentrant lock coordinates local writes,
  reads, cleanup, and cache access. Saved-image validation and reading happen
  under the same lock, so cleanup cannot remove a file between these steps.
- Capture listings (latest 50, sliced for smaller requests) and storage totals
  use shared 15-second caches. Capture writes and cleanup invalidate both.
  Changes made externally to the capture directory can take up to 15 seconds
  to appear in listing/statistics responses. Individual image/JSON reads are
  still validated against disk on every request.
- The Snapshots panel fetches JPEGs only while selected and the document is
  visible. Its graphs use wall-clock slots: paused periods remain empty and
  old samples expire after the 30-minute window. Stream metric collection on
  the server continues regardless of browser visibility.
- Stream and Settings live previews disconnect when the document is hidden.
  Stream metrics are fetched only on the visible Stream panel; capture history
  is polled only on the visible History panel. Status polling pauses while the
  document is hidden. Returning to the page resumes the relevant work.
- Snapshot, stream-metric, status, and History polling now use one cancellable
  request group at a time, a 10-second timeout, and a delay after completion
  (5 seconds for snapshots/metrics, 15 for History, 30 for status). Slow requests
  cannot build up overlapping polling cycles. Manual History refreshes share
  the same in-flight work.
- Preview elements no longer start streams before the selected panel is known.

## Scope

API paths, capture filenames, JSON fields, retention duration, camera controls,
Nginx streaming routes, and dependency requirements are preserved. Saved JPEGs
are read off-thread under the storage lock, rather than switching to FileResponse;
this preserves the cleanup/read coordination and existing response behavior.

The smaller review suggestions (font conversion, incremental metric responses,
status caching, batched V4L2 writes, and incremental History rendering) are not
part of this update. Keep the current single API worker: control state and
collector ownership remain process-local.

## Verification

Run from the project directory with the application dependencies installed:

```bash
python -m unittest discover -s tests -p 'test_performance*.py' -v
node --experimental-vm-modules --test tests/test_polling.mjs
```

Result: **12 backend tests and 6 JavaScript tests passed**.

The tests cover cache expiry/invalidation, defensive cache copies, unique
concurrent capture publication, interrupted writes, retention/read coordination,
HTTP response compatibility, responsive health requests during blocked storage
operations, cancellation, timeouts, rapid stop/start, visibility/tab selection,
and gaps in snapshot history. JavaScript dashboard checks use DOM/module
stand-ins, not a rendered browser or physical cameras.

The original attachment did not include the historical tests referenced by
TESTDOCUMENTATION.md. The three test files in this update are new focused
regressions; the historical suite has not been reconstructed or rerun.

The environment could not download the pinned requirements. API tests used the
pure-Python dependencies already bundled in the original ZIP: FastAPI 0.141.1,
Starlette 1.6.0, HTTPX 0.28.1, with the available Pydantic 2.13.5, on Python 3.12.14.
JavaScript tests used Node 24.19.0. The older versions in requirements.txt were
not separately tested. No production camera latency or browser rendering
benchmark is claimed.

## Deployment

Copy the updated source and dashboard files using the existing README update
procedure, preserving your production configuration, captures, camera configs,
and server virtual environment. Restart camera-api.service and hard-refresh the
dashboard. No Nginx or camera-capture service change is required for this update.

The ZIP contains the complete supplied source, assets, deployment examples,
documentation, and sample capture data, plus these changes and regression tests.
