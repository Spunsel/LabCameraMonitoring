Snapshot REST API

Take a snapshot from one camera. Receive the JPEG directly, or save it and receive a link to the image.

How it works

Use whiteboard or robot for {camera_id}. The API base is https://lab.bpm.in.tum.de/cameras.

1 · Return the image directly

Each GET takes the current picture and returns image/jpeg. The image is not saved to the server and has no History entry.

GET /api/v1/cameras/{camera_id}/snapshot.jpg

2 · Save the image and return a link

Put one camera ID in the URL and send an empty POST. The server saves one JPEG, generates an ID, and returns the complete image URL as plain text and in the Location response header.

POST /api/v1/cameras/{camera_id}/captures

POST returns 201 Created. The generated ID is part of the link; you can also use it with GET /api/v1/captures/{event_id} for metadata. An unknown camera returns 404. Saved pictures become eligible for automatic deletion after 2 days. Cleanup runs at service startup and hourly; deleted images then return 404.

GET /api/v1/captures/{event_id}/{camera_id}.jpg

Example · whiteboard

Get a picture directly and write the JPEG to whiteboard.jpg:

curl -fsS 'https://lab.bpm.in.tum.de/cameras/api/v1/cameras/whiteboard/snapshot.jpg' -o whiteboard.jpg

Alternatively, save the picture and print its link:

curl -fsS -X POST 'https://lab.bpm.in.tum.de/cameras/api/v1/cameras/whiteboard/captures'

Response body: a link to the saved JPEG (the ID changes for every capture):

https://lab.bpm.in.tum.de/cameras/api/v1/captures/capture-20260925T160000000Z-ab12cd34ef567890/whiteboard.jpg

Send a GET request to that link to retrieve the saved JPEG without taking another snapshot:

GET https://lab.bpm.in.tum.de/cameras/api/v1/captures/capture-20260925T160000000Z-ab12cd34ef567890/whiteboard.jpg

GET returns 200 OK and image/jpeg. To save your own capture locally:

saved_url=$(curl -fsS -X POST 'https://lab.bpm.in.tum.de/cameras/api/v1/cameras/whiteboard/captures')
curl -fsS "$saved_url" -o whiteboard.jpg
